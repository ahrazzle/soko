\begin{abstract}
\noindent AI coding agents wrote a Model Context Protocol (MCP) server, \texttt{soko-verified-mcp}, that replays, searches and certifies routes for the 66-room \emph{Heroes of Sokoban} trilogy used by the Sokoban Eval Frontier challenge. The same agents wrote its tests, and those tests passed while the server issued certificates that did not hold. This report catalogs those failures and records what still replays on the current tree. One defect was a boolean initialized to true, so a single interpreter could emit \texttt{VERIFIED} whenever the C++ engine was missing; it is fixed. A second is still open: the lower-bound wrapper labels a floor \texttt{VERIFIED} and says every shorter route was refuted when the search stopped at a node cap and returned no witness. An earlier draft of this paper reported a certified lower bound of 35 on Room III-14; a rerun of that prover aborts with a step-consistency failure and emits no final certificate, so the claim is withdrawn here. The results that replay are smaller: two 84-key routes on Room III-20 that agree across three local engines, a 5-step split-brain trace and a 486-state fenced safety check for a toy lease protocol, a 4-job schedule closed at cost 19, and a mutation audit that kills 10 of 10 planted rule bugs. The lesson for agent tooling is that a certificate should carry something a second checker can replay, and that the status word alone is the weakest part of the system.
\end{abstract}

\takeaway{Claim labels}{\texttt{PROVEN}: exhaustive check of a closed finite model. \texttt{VERIFIED}: a finite witness replayed by at least two independent engines. \texttt{KNOWN}: a public number imported from the frontier snapshot. \texttt{UB}: a route replayed locally as a win, which is an upper bound only. \texttt{CONJECTURE}: an untested explanation or an open optimality question. These are the paper's labels. Section~\ref{sec:limits} lists places where the server prints \texttt{VERIFIED} or \texttt{PROVEN} without meeting them.}

\section{Setting}

The Sokoban Eval Frontier challenge \cite{banteg2026announce,sokobanteg2026frontier} opens every room of Jonah Ostroff's PuzzleScript trilogy \cite{ostroff2026heroes} with the shortest route a language model found in banteg's evaluation runs \cite{banteg2026sokoban}. The 11 November 2026 announcement \cite{banteg2026announce} gives the starting state: the best segment run of the trilogy is 3,819 inputs, models matched the proven optimum in 44 of 66 rooms, the holdout routes for the other 22 rooms total 3,064 keys, and the trilogy floor is 3,000. Three rooms were open: III-14 (floor 43, known 48, model 116), III-20 (74, 85, 145) and III-21 (268, 316, 589).

The trilogy is harder to model than classical Sokoban. Six heroes follow different movement laws (the Fighter pushes chains, the Thief pulls, the Wizard swaps by projectile, the Priest shields neighbours, the Bard moves charmed objects inside a $5\times 5$ aura, and the Druid turns crates into walls and walls into crates), and PuzzleScript resolves rules synchronously. Agent-written engines drift from these semantics in small ways, which is why the server replays every route on more than one engine.

\texttt{soko-verified-mcp} is the server under study. On the tree this paper is committed to, it registers 19 MCP tools over stdio, 12 Sokoban tools (\texttt{soko\_*}) and 7 domain-general tools (\texttt{formal\_*}), together with 6 resources and 4 prompts. AI agents wrote the engines, the search code, the tests and most of the documentation; human review came through pull requests and independent agent audits. This is the setting the report is about: agents writing both a solver and the checker that is supposed to keep the solver honest.

\section{Related Work}

Lower bounds for Sokoban search have a long history. Junghanns and Schaeffer's Rolling Stone combined IDA* with deadlock tables, pattern search and lower-bound enhancements on the 90-level XSokoban suite \cite{junghanns2001sokoban}. Culberson and Schaeffer introduced pattern databases as admissible heuristics \cite{culberson1998pdb}. Pereira, Ritt and Buriol built instance-dependent pattern databases for Sokoban, where the goal of each stone is unknown in advance \cite{pereira2013instance}, and Pereira, Holte, Schaeffer, Buriol and Ritt extended this to multiple intermediate goal states and raised the number of optimally solved standard instances from 20 to 28 \cite{pereira2016improved}. Shoham and Schaeffer's FESS algorithm, implemented in the Festival solver, is the first program to solve all 90 XSokoban levels \cite{shoham2020fess}. The quotient argument in Section~\ref{sec:prop} is the standard abstraction argument behind this line of work. The pair abstraction built for Room III-14 is an application of it to a PuzzleScript variant.

The invariant engine follows Houdini \cite{flanagan2001houdini}. The lease example uses fencing tokens as described by Kleppmann \cite{kleppmann2016fencing} and logical clocks in the sense of Lamport \cite{lamport1978time}. \texttt{PROVEN}, \texttt{VERIFIED}, \texttt{KNOWN}, \texttt{UB} and \texttt{CONJECTURE} are this paper's own labels, defined in the box after the abstract.

\section{Case Study: A Withdrawn III-14 Certificate}
\label{sec:iii14}

Version 1.0 of this paper claimed that an exact-state A* search with a pair-atom pattern database raised the III-14 lower bound from 9 to 35 in about 35 seconds, with zero step-consistency violations over $1.108\times 10^{8}$ edges, after catching 22,658 live 64-bit hash collisions. That claim is withdrawn.

A rerun of \texttt{cpp/frontier\_iii14\_iii20\_prover.cpp}, built with \texttt{g++ -O3 -pthread -std=c++20}, prints an initial heuristic of 24 and then a completed layer at 35 (27,656,589 unique states, 5,348 collisions, 44,472,706 edges). On one machine the layer at 35 was reached after 22.25\,s; a second host took 30.68\,s for the same layer, so the clock is a property of the host. It continues to a layer at 36 (31,459 collisions, 135,254,050 edges), prints \texttt{STEP INCONSISTENCY DETECTED!}, and exits with status 2. It emits no \texttt{FINAL\_CERT}. The figures 22,658 and $1.108\times 10^{8}$ appear only in an earlier dossier and in the v1.0 draft. Three further points narrow what the search measured:
\begin{itemize}
  \item The prover targets the legacy 14$\times$7 fixture. The catalog board for III-14 is 15$\times$7. Every 14$\times$7 number in this section is a fixture result.
  \item The collision counter increments on every open-address probe that meets the same hash and a different state, including repeat inserts. It counts probes, and the v1.0 reading of it as distinct colliding pairs was wrong. Two smaller counts in v1.0 (11 collisions in a 6\,s IDA* run and 1,014 in a 10\,s A* run) have no log behind them.
  \item The $3.97\times 10^{7}$ figure is the length of the pair-atom table array, including unreachable slots.
\end{itemize}
The MCP wrapper is weaker still. \texttt{soko\_prove\_floor} on \texttt{fixture:III-14} stops at its 4,500,000-state pool cap after about 9\,s on one host, well inside its 36\,s budget. It returns floor 32 with no witness and labels the result \texttt{VERIFIED}. That is the open F-04 path from Table~\ref{tab:audit}.

A failed consistency check does not by itself produce a route shorter than 48; an inconsistent heuristic can still be admissible. It does mean the search is not an instance of Proposition~\ref{prop:quotient}, and the printed layer bounds carry no certificate. The public III-14 floor stays at 43 and the best known route at 48.

\takeaway{Conjecture (column 6)}{v1.0 explained the five-key gap between 43 and 48 by crates on column 6 being pushed into an open column 7 under the Bard's aura unless the Druid spends extra keys. That explanation is untested and argued on the 14$\times$7 fixture. Its ``38 atoms'' invariant is the wall count of that fixture, which differs from the catalog board. It stays here as a conjecture to test on the 15$\times$7 board.}

\section{What the Quotient Argument Covers}
\label{sec:prop}

The lower-bound tools rest on one classical result. It is stated here on its own, apart from any particular heuristic.

\begin{proposition}[Quotient lower bound]
\label{prop:quotient}
Let $\mathcal{M}$ be a transition system with states $\mathcal{S}$, non-negative step costs $c(s,a,s')$ and goals $G$, and let $\pi:\mathcal{S}\to\mathcal{Q}$ map onto a finite abstract graph with weights $w\ge 0$ and goals $G_{\mathcal{Q}}$. If every concrete step $(s,a,s')$ has an abstract edge $(\pi(s),\pi(s'))$ with $w(\pi(s),\pi(s'))\le c(s,a,s')$, and $\pi(G)\subseteq G_{\mathcal{Q}}$, then the abstract distance $d_{\mathcal{Q}}(\pi(s),G_{\mathcal{Q}})$ is at most the concrete distance $d_{\mathcal{M}}(s,G)$ for every $s$, and it satisfies $d_{\mathcal{Q}}(\pi(s),G_{\mathcal{Q}})\le c(s,a,s')+d_{\mathcal{Q}}(\pi(s'),G_{\mathcal{Q}})$ on every concrete step.
\end{proposition}
\begin{proof}
A concrete path to a goal projects to an abstract walk to an abstract goal of no greater total weight, so the abstract distance is a lower bound. Step consistency follows from the triangle inequality for shortest-path distances in the abstract graph.
\end{proof}

The proposition assumes its premises for the whole transition system. The code checks them in one place: \texttt{formal\_\allowbreak certify\_\allowbreak lower\_\allowbreak bound} in quotient mode, on a closed, fully enumerated concrete graph, adds one abstract edge per concrete edge at that edge's cost, runs reverse Dijkstra, and rejects the certificate if any concrete edge violates the inequality. It refuses an incomplete graph. The C++ pair-atom database for III-14 is a separate, hand-written reverse search; nothing in the repository shows that every PuzzleScript step maps to one of its edges, and the case study above shows a consistency failure. A truncated inductive potential is a different matter again: it says nothing about edges the search never explored (Section~\ref{sec:limits}).

For II-22, III-11 and III-15 the matching public floors are imported observations, and the catalog itself notes that importing them does not establish a lower bound. The two \texttt{PROVEN} rows are the ones where the local search closed with a witness whose length equals the floor, which the F-04 path does not affect.

\textbf{III-20.} The room has a vertical reflection of its walls, goblins and goals, but the heroes sit asymmetrically and the hero-switch key cycles in a fixed order, so a reflected route is a new route. Reflecting the earlier 87-key record and polishing it with a tube beam search gave two 84-key routes, one key under the 85-key holdout. \texttt{python3 -m soko\_mcp verify --room III-20} returns \texttt{VERIFIED}, length 84 and agreement across three engines for both. The frontier snapshot lists the record at 84 (holder \texttt{a1kindus}, previous length 87), and the trilogy's shortest-known sum is 3,063, one under the 3,064 holdout total. Local replay uses the repository's engines, and the frontier's own replay uses the original browser build. No route under 84 was found; the search was a beam search and was not exhaustive.

\textbf{Lease protocol.} The test suite encodes a two-gateway lease protocol as a tuple-based spec and an integer-packed implementation. Without fencing, \texttt{formal\_solve\_system} finds the 5-step split-brain trace \texttt{s1\_acq} $\to$ \texttt{timeout} $\to$ \texttt{s2\_acq} $\to$ \texttt{s2\_commit} $\to$ \texttt{s1\_commit}. With monotonic epoch fencing, Houdini returns \texttt{PROVEN} over all $3\times 3^{4}\times 2 = 486$ syntactic states of the test's model, with epochs in $\{0,1,2\}$. This is a check of a toy model; Section~\ref{sec:limits} notes that the global safety check reads the spec invariant only.

\textbf{Scheduling.} A 4-job, 2-cluster schedule with precedence and a switch-over cost of 5: window LNS takes a cost-29 seed to 19, an 18-state quotient proves a lower bound of 19 on the closed graph, and an exaggerated potential is rejected with \texttt{REJECTED\_\allowbreak STEP\_\allowbreak CONSISTENCY\_\allowbreak VIOLATION}. The optimum is $3+4+5+3+4 = 19$.

\textbf{Mutation audit.} \texttt{python3 -m soko\_mcp audit} kills 10 of 10 planted PuzzleScript rule bugs with 0 mismatches across 11 cross-oracle parity vectors.

The lease and scheduling results are small and classical \cite{lamport1978time,kleppmann2016fencing}. They show the tool contract working on non-puzzle domains; they are not results in distributed systems or scheduling.

\section{Limitations and Future Work}
\label{sec:limits}

The audit found more places where the server's status words outrun its checks. Code changes are out of scope for this report, so each is listed as future work.
\begin{itemize}
  \item \textbf{F-04 witness hole.} \texttt{prove\_floor\_verified} should return \texttt{VERIFIED} only for a winning witness whose length equals the floor together with a completed exhaustive search below that length. A floor with no witness and \texttt{exact\_optimum\_reached} false should be rejected, and so should a floor that only matches a winning witness. The I-1 row at 8 and the III-22 row at 9 meet this bar. \texttt{tests/test\_search\_bounds.py} states the stricter contract.
  \item \textbf{Truncated potentials.} On a 20-state chain with a cost-0 jump at state 10 and \texttt{max\_\allowbreak concrete\_\allowbreak states=6}, \texttt{formal\_\allowbreak certify\_\allowbreak lower\_\allowbreak bound} reports a certified lower bound of 15 under the status \texttt{VERIFIED\_\allowbreak ON\_\allowbreak BOUNDED\_\allowbreak REACHABLE\_\allowbreak SUBGRAPH}, while the true cost is 10. A bound checked on a prefix of the graph is not a bound on the edges beyond it. This chain should become a regression test that must reject.
  \item \textbf{\texttt{PROVEN} reads the spec only.} With a constant observation projection, a step function that diverges after state 1 still locks \texttt{VERIFIED}. An implementation whose invariant is false from state 1 also locks, and the invariant search then returns \texttt{PROVEN} and \texttt{EXHAUSTIVE\_\allowbreak GLOBAL\_\allowbreak SAFETY\_\allowbreak PROOF}. The Dijkstra loop and Houdini's target check read \texttt{spec.invariant} only.
  \item \textbf{Triage and ledger.} \texttt{formal\_triage\_portfolio} returns \texttt{VERIFIED} for a caller-supplied floor with no proof, and \texttt{formal\_export\_ledger} accepts the two-character digest \texttt{"ab"} as \texttt{VERIFIED}. The v1.0 claim ledger and its hash pin are removed from this version; a ledger should pin digests of files that exist.
  \item \textbf{Open rooms.} III-14 on $[43,48]$, III-20 on $[74,84]$ and III-21 on $[268,316]$ remain open. The III-14 work should move to the 15$\times$7 catalog board.
\end{itemize}

\section{Lessons for Agent Tooling}

Three patterns recur. First, agents write tests that check the shape of a result, and a status string is part of the shape, so a green suite says little about soundness. Second, numbers migrate: a figure from one run lands in a dossier, then in a paper, and survives after the code that produced it has changed. Third, a certificate that a second checker cannot replay reduces to the searcher's own word. The fixes that held in this project share one property: they made the checker compare something concrete, such as a per-frame digest across engines or a witness of the claimed length. Requiring that of every \texttt{VERIFIED} and \texttt{PROVEN} label is the next step.
